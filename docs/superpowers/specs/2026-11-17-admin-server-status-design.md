# 관리자 웹 서버 상태 · 메뉴 숫자 배지 설계 (2026-11-17)

## 왜
사용자(운영자)가 관리자 웹을 열어 두고 **서버 이상을 한눈에** 보고, **처리할 일이 몇 건인지** 메뉴에서 바로 보려고. 관제용 알림(디스코드 · 메일)은 이번에 하지 않는다(사용자 「일단은 알림은 빼자」).

## 목표
1. 새 메뉴 "서버 상태"(작업 기록 위): 최근 3시간 서버 숫자 · 그래프 · 이상 목록.
2. 왼쪽 메뉴 빨간 숫자 배지: 서버 상태(새 이상 수) · 인증샷 검수 · 졸업생 · 신고 · 문의(대기 건수).

## 하지 않는 것
- 자동 새로고침(사용자 「1분마다 저절로 새로고침하지마, 내가 새로고침할게」) — 화면 [새로고침] 버튼 · 페이지 새로 열기 때만 읽는다.
- 디스코드 · 메일 · 휴대폰 알림, 백그라운드 감시.
- 새 DB 표 · 운영 DB 변경, Crashlytics 숫자(Firebase 콘솔 링크로 대신).

## 제약
- 서버는 Cloud Monitoring API 를 **읽기만** 한다. 권한 `roles/monitoring.viewer` 는 11-17 사용자 허락으로 서버 계정에 부여 끝.
- 공개 저장소: 프로젝트 id · 계정 이메일을 코드 · 문서에 적지 않는다(`settings.google_cloud_project` 를 쓴다).
- `backend/app/core/errors.py` 문구는 바꾸지 않는다.
- 서버 배포 · 관리자 웹 반영은 사용자 직접 허락.

## 접근
- **고른 것: 화면을 열 때 서버가 구글 숫자를 대신 읽는다.** 이상 판정은 응답을 만들 때 계산(저장 없음). "확인"한 이상은 열쇠(칸 시각|종류)로 브라우저(localStorage)에 둔다 — DB 가 필요 없다. PC · 휴대폰은 따로 센다(대장 판단). 처음엔 "확인 시각" 하나였으나, 이상 시각이 5분 칸 시작이라 확인 직후 같은 칸에 생긴 이상을 놓쳐 열쇠 방식으로 바꿨다(구현 중 결정). 로그아웃하면 화면 상태를 비운다.
- 버린 것: 구글 알림 → 서버 저장 → 디스코드(알림을 뺐으므로 불필요) / Looker Studio(15분~하루 늦음, 사용자 화면 밖).

## 정해진 값
- 창 3시간, 칸 5분. "지금" 숫자는 마지막 15분(구글 숫자가 1~3분 늦어서 마지막 칸만 보면 비어 보임).
- 이상 판정(칸마다, 대장 판단 — 상수로 둔다):
  - `errors`: 5xx ≥ 3건
  - `error_rate`: 요청 ≥ 20건이고 5xx 비율 ≥ 5%
  - `slow`: 요청 ≥ 20건이고 중앙값(p50) ≥ 1초. p95 로 판정하지 않는다 — 아바타 만들기(20~27초)가 같은 서버에 들어와 한산할 때 p95 를 늘 끌어올린다.
- 대기 건수: 인증샷 검수 = 기존 `/admin/stats` 의 `pending_proofs`, 신고 = `open_reports`, 졸업생 = `graduate_verification_requests.status = pending`, 문의 = `inquiries.status in (new, in_progress)`(아직 답 안 한 것, 대장 판단).
- 배지: 0 이면 숨김, 100 이상 "99+". 색 · 크기는 pen 시안 값.
