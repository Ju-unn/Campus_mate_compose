## Global Constraints

- `faq` 권한: `authenticated` = `select` 만, `anon` = 없음, `service_role` = `select` · `insert` · `update` · `delete`. `revoke all … from anon, authenticated, service_role` 다음에 준다(ERD §2 62~66줄).
- 묶음 순서와 이름(DESIGN §8.13): **카드·매칭 / 하트·결제 / 사진·프로필 / 지인 리뷰 / 안전·신고 / 계정** = `card_matching` `heart_payment` `photo_profile` `friend_review` `safety` `account`. pen 이름이 다르면 pen 이 이긴다.
- 문구는 `FAQ_초안.md` 의 표에서 **스크립트로 옮긴다**(Task D1 Step 2). 손으로 옮겨 적지 않는다.
- 검색: 앞뒤 공백을 깎은 검색어로 질문 · 답변을 부분일치로 찾는다. 영문은 대소문자를 가리지 않는다.
- 펼침은 한 번에 하나(DESIGN §8.13). 펼침 · 접힘 시간은 `AppMotion.standard`(220ms) · `AppMotion.standardCurve`.
- 새 의존성 없음(pubspec 그대로). `dart format` 을 돌리지 않는다. CRLF 파일은 Edit 또는 python `newline=''` 로만 고친다.
- 잉크(COMMON §4-2): 누르는 줄마다 자기 Material. 테스트로 "가장 가까운 Material 크기 == 줄 크기"를 잡는다.
- 글자 크기: 높이를 고정하지 않는다(`minHeight` 만). 2.0배에서 잘림 · 넘침이 없어야 한다.
- 이 계획서와 pen 이 다르면 **pen 이 이긴다**(단 문구 · 묶음 코드 · 공개 범위는 위 결정이 이긴다).

## Review Focus

1. **앱이 모르는 묶음 값이 표에 생기면**(대시보드에서 enum 을 늘렸는데 앱은 옛 버전) 그 행만 빠지고 나머지는 그려져야 한다. → Task A1 `모르는 묶음 행은 버린다`.
2. **처음 켠 폰이 오프라인이라 받지도 못하고 캐시도 없으면** 설정 줄이 없어야 하고, 캐시가 있으면 캐시로 그려야 한다. → Task A2 `못 받으면 캐시` · `캐시도 없으면 빈 목록` · Task A5 `받지도 못하고 캐시도 없어 빈 목록이면 줄이 없다`.
3. **캐시 파일이 깨졌거나 디스크에 못 쓰면** 화면이 막히지 않아야 한다(읽기 = 빈 목록, 쓰기 실패 = 받은 목록은 그대로). → Task A2 `깨진 파일은 빈 목록` · `저장이 실패해도 받은 목록을 준다`.
4. **검색어가 답변에만 있거나, 앞뒤에 공백이 있거나, 걸리는 게 하나도 없을 때.** 답변만 맞아도 걸리고, 공백은 무시하고, 0개면 빈 화면 대신 한 줄 안내가 보여야 한다. → Task A3 `faqSections` 테스트 3개 · Task A4 `걸린 게 없으면 안내`.
5. **글자를 2.0배로 키우면** 긴 질문(510 "누가 가입할 수 있나요? 재학생이 아니어도 되나요?")과 펼친 답변이 잘리지 않아야 한다. → Task A4 `2.0배에서 넘침이 없다`.

```dart
/// FAQ 묶음(ERD `faq_category`). 화면 21 은 이 순서대로 절을 늘어놓는다(DESIGN §8.13).
enum FaqCategory {
  cardMatching('card_matching', '카드·매칭'),
  heartPayment('heart_payment', '하트·결제'),
  photoProfile('photo_profile', '사진·프로필'),
  friendReview('friend_review', '지인 리뷰'),
  safety('safety', '안전·신고'),
  account('account', '계정');

  const FaqCategory(this.wire, this.label);

  /// 표에 적힌 값.
  final String wire;

  /// 묶음 제목.
  final String label;
}

/// `faq` 한 줄.
class FaqItem {
  const FaqItem({
    required this.id,
    required this.category,
    required this.question,
    required this.answer,
    required this.sortOrder,
  });

  final String id;
  final FaqCategory category;
  final String question;
  final String answer;
  final int sortOrder;

  /// 캐시 파일 한 줄 — [parseFaqRows] 가 표 행과 같은 모양으로 다시 읽는다.
  Map<String, Object> toJson() =>
      {'id': id, 'category': category.wire, 'question': question, 'answer': answer, 'sort_order': sortOrder};
}

/// 표 행이나 캐시 파일을 읽는다. 앱이 모르는 묶음(대시보드에서 enum 을 먼저 늘린 경우)은 버린다 —
/// 새 앱이 나오기 전까지 그 묶음만 안 보이고 나머지는 그대로 그린다.
List<FaqItem> parseFaqRows(List<dynamic> rows) => [
      for (final row in rows.cast<Map<String, dynamic>>())
        if (FaqCategory.values.where((c) => c.wire == row['category']).firstOrNull case final category?)
          FaqItem(
            id: row['id'] as String,
            category: category,
            question: row['question'] as String,
            answer: row['answer'] as String,
            sortOrder: row['sort_order'] as int,
          ),
    ];
```

```dart
abstract interface class FaqCache {

class FileFaqCache implements FaqCache {
  FileFaqCache(this._directory);

  final Future<Directory> Function() _directory;
  static const _fileName = 'faq_cache.json';

  @override
  Future<List<FaqItem>> load() async {
    try {
      final file = await _file();
      if (!await file.exists()) return const [];
      return parseFaqRows(jsonDecode(await file.readAsString()) as List<dynamic>);
    } on Object {
      // 깨진 파일은 없는 것과 같다 — 다음에 받으면 덮어쓴다.
      return const [];
    }
  }

  @override
  Future<void> save(List<FaqItem> items) async {
    final file = await _file();
    await file.writeAsString(jsonEncode([for (final item in items) item.toJson()]));
  }

  Future<File> _file() async => File('${(await _directory()).path}/$_fileName');
}
```

```dart
import 'package:campus_mate/faq/model/faq_item.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

/// 21 한 절 — 묶음 제목과 그 아래 문항들.
typedef FaqSection = ({FaqCategory category, List<FaqItem> items});

/// 묶음(enum 순서) → 묶음 안 sort_order 로 늘어놓는다. 검색어는 앞뒤 공백을 깎고 질문 · 답변을 부분일치로 찾는다
/// (DESIGN §8.13 "단순 부분일치면 충분하다"). 걸린 게 없는 묶음은 제목째 뺀다.
List<FaqSection> faqSections(List<FaqItem> items, String query) {
  final needle = query.trim().toLowerCase();
  bool hit(FaqItem item) =>
      item.question.toLowerCase().contains(needle) || item.answer.toLowerCase().contains(needle);
  return [
    for (final category in FaqCategory.values)
      if ((items.where((i) => i.category == category && hit(i)).toList()
            ..sort((a, b) => a.sortOrder.compareTo(b.sortOrder)))
          case final found when found.isNotEmpty)
        (category: category, items: found),
  ];
}

/// 21 의 검색어와 펼친 문항.
class FaqUiState {
  const FaqUiState({this.query = '', this.expandedId});

  final String query;
  final String? expandedId;
}

final faqViewModelProvider = NotifierProvider.autoDispose<FaqViewModel, FaqUiState>(FaqViewModel.new);

class FaqViewModel extends Notifier<FaqUiState> {
  @override
  FaqUiState build() => const FaqUiState();

  void search(String query) => state = FaqUiState(query: query, expandedId: state.expandedId);

  /// 한 번에 하나만 펼친다(DESIGN §8.13 — 여러 개가 열리면 스크롤 위치를 잃는다). 펼친 걸 다시 누르면 접는다.
  void toggle(String id) => state = FaqUiState(query: state.query, expandedId: state.expandedId == id ? null : id);
}
```
