```jsonc

  "interest_tags": ["카페가기", "여행", "요리"],     // 15c 칩 · 태그 편집 채우기
  "my_traits": ["유머러스", "성실한", "차분한"],

  "preferred_impression_types": ["kind"],

  ],
```

- `nickname_changeable_at` 은 서버가 `get_now` 로 판정한다(앱 시계를 믿지 않는다 — 잠금 판정과 PATCH 409 가 같은
  함수를 본다). `nickname_changed_at + 30일` 이 지금보다 뒤면 그 때, 아니면(또는 `nickname_changed_at` 이 null 이면)
  null. pen 15d-2 문구가 남은 날이 아니라 날짜라(C6) 날짜를 준다.

- `photo_urls` 와 `photos[].url` 은 같은 서명을 **한 번만** 만들어 두 곳에 싣는다. `photo_urls` 는 앱이 `photos` 로
  옮긴 뒤에도 남긴다(서버가 먼저 배포되는 동안 옛 앱이 읽는다).
- 요청은 여전히 가드 뒤 **1번**이다(entitlements 는 embed. 1:1 이라 객체 또는 null 로 온다).

### 2-2. `PUT /me/photos` (새로) — 사진 한 번에 저장(U2)

multipart:

- `layout`: JSON 문자열. 칸 순서대로 `{"keep": "<photo id>"}` 또는 `{"new": <photos 파일 번호>}`. 2~4칸.
- `avatar_source`: 아바타 원본이 될 칸 번호(0부터).
- `photos`: 새 사진 파일 0~4장(같은 이름 `photos` 로 여러 개).

| 경우 | 응답 |
| --- | --- |
| 저장됨 | 200 `{"ok": true}` |
| layout 이 JSON 이 아님 · 2 미만 · 4 초과 · `new` 번호가 파일 수와 안 맞거나 겹침 · `keep` 겹침 · `avatar_source` 범위 밖 | 422 `INVALID_INPUT`(기존 "입력한 값을 다시 확인해 주세요") |
| `keep` id 가 지금 내 사진이 아님(이미 지워졌거나 남의 것) | 409 `PHOTOS_CHANGED` "사진이 바뀌었어요, 다시 열어 주세요" (**errors.py 새 줄**) |
| 새 사진 형식 불명 | 400 `PHOTO_UNREADABLE`(기존) |
| 새 사진 부적절(SafeSearch) | 422 `PHOTO_NOT_SAFE`(기존) |

서버 순서 — **④ 앞에서 막히면 아무것도 안 바뀐다**: ① layout 검사 → ② 내 사진 행 읽기 · keep 검사 → ③ 새 사진 전부
형식 · SafeSearch → ④ 새 사진 Storage 업로드 → ⑤ 빠진 행 지우기 → ⑥ 원본 표시 전부 내리기 → ⑦ 최종 행 upsert **한
번**(남길 행은 id 그대로, 새 행은 서버가 만든 uuid, position 0..n-1, 원본 1장) → ⑧ 빠진 사진 파일을 Storage 에서
지우기.

- ⑤~⑦ 이 세 요청이라 ⑦ 이 실패하면 "빠진 행은 지워졌고, 남긴 행은 옛 자리 · 원본 없음" 으로 남는다(사진 수는
  남긴 만큼. position 에 구멍이 나도 읽는 쪽은 정렬만 한다). 앱은 실패 문구를 보이고 화면을 다시 읽는다.
  코드에 `ponytail:` 주석 — 한 트랜잭션이 필요해지면 DB 함수로 옮긴다(마이그레이션 필요).
- ⑦ 은 `POST /profile_photos?on_conflict=id` + `Prefer: resolution=merge-duplicates`. 한 문장이라 deferred 유니크는
  커밋 때 한 번 본다 — 두 사진의 자리 맞바꿈이 통과한다(S1 pgTAP 이 이 가정을 못박는다). 아바타 원본 부분 유니크는
  즉시 검사라 ⑥ 이 먼저다.

### 2-3. `POST /me/avatar/regenerate` (새로) — 15b "만들기"

응답 모양은 온보딩 `POST .../avatar/generate` · `GET .../avatar/status` 와 **같다**
(`{"status", "avatar_url", "compensation_hearts"}`) — 앱 파서 하나(`HttpAvatarRepository._toOutcome`)로 읽는다.
기다리는 동안은 기존 `GET /profile-onboarding/avatar/status` 를 그대로 묻는다(가장 최근 시도를 보여 준다).

| 순서 | 경우 | 응답 |
| --- | --- | --- |
| 1 | 큐 설정 없음 | 503 `AVATAR_QUEUE_UNAVAILABLE`(기존) |
| 2 | ready 아바타가 하나도 없음(온보딩 전) | 409 `AVATAR_NOT_CREATED` "아바타를 먼저 만들어 주세요" (**errors.py 새 줄**) |
| 3 | 아바타 원본 사진 없음 | 409 `AVATAR_SOURCE_REQUIRED`(기존) |

| 5 | 비용이 0 보다 큰데 잔액 < 비용 | 402 `HEARTS_NOT_ENOUGH` "하트가 모자라요" (**errors.py 새 줄**, 문구는 D2 답에 따라 바뀔 수 있다) |

### 2-4. 워커 `POST /tasks/avatar-generate` (고침)

- 생성 **전**에 `ready_before = count_ready_avatars(profile_id)` 를 센다(카운트 관문 (2) 옆).
- (4) 관문을 통과한 뒤:
  - 실패 + 5회째 + `ready_before == 0` → 지금처럼 기본 아바타 + 하트 10. **`ready_before >= 1` 이면 그냥 `failed`**(T3).

## 3. DB 변경 판단 — ~~없음~~ → `grant_hearts` 본문 하나(D9 (가), Task D1)

**S1 에서 뒤집혔다(campus-coder 발견, 나 탭이 임시 표로 다시 재현 09-28).** `grant_hearts` 의 잔액 쓰기는
`insert ... values (p_amount) on conflict do update set heart_balance = 잔액 + excluded` 인데, Postgres 는 check 를
**제안 행**(잔액 = `p_amount` = 음수)에 먼저 건다 → 잔액 320 에서 10 을 써도 23514. 그대로 두면 `spend_hearts` 가 늘
False 라 유료 다시 만들기가 전부 공짜가 된다(경고 로그만).

고침(D9 (가) — 로컬 롤백 트랜잭션에서 pgTAP 10/10 확인됨. 파일 · 테스트는 Task D1):

```sql
-- 하트 쓰기(음수)가 늘 막히던 것 고침. insert ... on conflict do update 는 check 를 제안 행(잔액 = p_amount)에
-- 먼저 건다 — 음수면 잔액이 넉넉해도 23514. 행을 0 으로 보장한 뒤 update 로 더한다(적립 동작은 그대로).
create or replace function public.grant_hearts(p_profile_id uuid, p_amount integer, p_reason public.heart_reason, p_ref_id uuid default null)
returns void
language plpgsql
set search_path = ''
as $$
begin
  insert into public.heart_transactions (profile_id, amount, reason, ref_id)
  values (p_profile_id, p_amount, p_reason, p_ref_id);

  insert into public.entitlements (profile_id) values (p_profile_id)
  on conflict (profile_id) do nothing;

  update public.entitlements
    set heart_balance = heart_balance + p_amount, updated_at = now()
    where profile_id = p_profile_id;
end;
$$;
```

`create or replace` 는 권한을 그대로 두지만 `set search_path` 는 다시 적어야 한다(`20260920061752_fix_slice2_advisor_warnings.sql`). 시그니처 ·
부르는 곳(`hearts.py` · `create_poll_functions.sql`) 그대로. ERD 그림 변화 없음(함수 본문).

```sql
create or replace function public.grant_hearts(p_profile_id uuid, p_amount integer, p_reason public.heart_reason, p_ref_id uuid default null)
returns void
language plpgsql
set search_path = ''
as $$
begin
  insert into public.heart_transactions (profile_id, amount, reason, ref_id)
  values (p_profile_id, p_amount, p_reason, p_ref_id);

  insert into public.entitlements (profile_id) values (p_profile_id)
  on conflict (profile_id) do nothing;

  update public.entitlements
    set heart_balance = heart_balance + p_amount, updated_at = now()
    where profile_id = p_profile_id;
end;
$$;
```

```python
"""사진 한 번에 저장(PUT /me/photos)의 칸 배치를 읽는다. 저장소를 모르는 순수 함수라 따로 둔다."""
import json

MIN_PHOTOS, MAX_PHOTOS = 2, 4  # 온보딩 04-2 와 같다(profile_photos 주석 "최소 2장", check 0~3)


def parse_layout(raw: str, new_count: int, avatar_source: int) -> list[str | int]:
    """칸 순서대로 남길 사진 id(str) 또는 새 파일 번호(int)를 돌려준다. 하나라도 안 맞으면 ValueError.

    올린 파일은 전부 한 번씩 써야 한다 — 안 쓴 파일을 받아 두면 SafeSearch · 업로드 값만 나가고 아무 데도 안 붙는다."""
    try:
        slots = json.loads(raw)
    except json.JSONDecodeError as error:
        raise ValueError("layout 이 JSON 이 아니다") from error
    if not isinstance(slots, list) or not MIN_PHOTOS <= len(slots) <= MAX_PHOTOS:
        raise ValueError("칸은 2~4개다")
    parsed: list[str | int] = []
    for slot in slots:
        if isinstance(slot, dict) and slot.keys() == {"keep"} and isinstance(slot["keep"], str):
            parsed.append(slot["keep"])
        elif isinstance(slot, dict) and slot.keys() == {"new"} and type(slot["new"]) is int:
            parsed.append(slot["new"])
        else:
            raise ValueError("칸은 keep(문자열) 또는 new(정수) 하나다")
    kept = [s for s in parsed if isinstance(s, str)]
    new = [s for s in parsed if isinstance(s, int)]
    if len(set(kept)) != len(kept) or sorted(new) != list(range(new_count)):
        raise ValueError("같은 사진을 두 번 쓰거나 올린 파일과 번호가 안 맞는다")
    if not 0 <= avatar_source < len(parsed):
        raise ValueError("아바타 원본 칸 번호가 범위 밖이다")
    return parsed
```

```python
@router.put("/me/photos")
async def save_photos(
    layout: str = Form(),
    avatar_source: int = Form(),
    photos: list[UploadFile] = File(default=[]),
    caller: Caller = Depends(get_verified_caller),
    vision_client: vision.ImageAnnotatorAsyncClient = Depends(get_vision_client),
) -> dict[str, bool]:
    """실제 사진 교체(U2) — 남길 사진은 id, 새 사진은 파일. 순서는 계획서 2-2 ①~⑧, ④ 앞에서 막히면 아무것도 안 바뀐다."""
    settings, client, profile_id = caller
    try:
        slots = parse_layout(layout, new_count=len(photos), avatar_source=avatar_source)
    except ValueError:
        raise HTTPException(status_code=422, detail=errors.INVALID_INPUT) from None

    repo = MeRepository(settings.postgrest_url, settings.supabase_service_role_key, client)
    current = {row["id"]: row for row in await repo.fetch_photo_rows(profile_id)}
    if any(isinstance(slot, str) and slot not in current for slot in slots):
        raise HTTPException(status_code=409, detail=errors.PHOTOS_CHANGED)

    # ③ 전부 먼저 본다 — 셋째 장이 부적절하면 첫째 장도 올리지 않는다.
    checked: list[tuple[bytes, str]] = []
    for photo in photos:
        data = await photo.read()
        content_type = student_id_content_type(data)
        if content_type is None:
            raise HTTPException(status_code=400, detail=errors.PHOTO_UNREADABLE)
        if not await check_safe_search(vision_client, data):
            raise HTTPException(status_code=422, detail=errors.PHOTO_NOT_SAFE)
        checked.append((data, content_type))

    storage = ProfilePhotoStorage(settings.storage_url, settings.supabase_service_role_key, client)
    uploaded = [await storage.upload(profile_id, data, content_type) for data, content_type in checked]

    kept_ids = {slot for slot in slots if isinstance(slot, str)}
    dropped = [row for row_id, row in current.items() if row_id not in kept_ids]
    # ponytail: ⑤~⑦ 이 세 요청이다. ⑦ 이 실패하면 빠진 행은 지워지고 남긴 행은 옛 자리 · 원본 없음으로 남는다
    # (앱은 다시 읽는다). 한 트랜잭션이 필요해지면 DB 함수로 옮긴다(마이그레이션).
    if dropped:
        await repo.delete_photo_rows(profile_id, [row["id"] for row in dropped])
    await repo.clear_avatar_source(profile_id)
    await repo.upsert_photo_rows([
        {
            "id": slot if isinstance(slot, str) else str(uuid4()),
            "profile_id": str(profile_id),
            "storage_path": current[slot]["storage_path"] if isinstance(slot, str) else uploaded[slot],
            "position": position,
            "is_avatar_source": position == avatar_source,
        }
        for position, slot in enumerate(slots)
    ])
    # ⑧ 행이 먼저 바뀐 뒤에 지운다 — 거꾸로면 잠깐 동안 없는 파일을 가리키는 행이 생긴다.
    for row in dropped:
        await storage.delete(row["storage_path"])
    return {"ok": True}
```

```python
def nickname_changeable_at(changed_at: datetime | None, now: datetime) -> datetime | None:
    """닉네임 잠금이 풀리는 때. 지금 바꿀 수 있으면 None."""
    if changed_at is None:
        return None
    changeable_at = changed_at + NICKNAME_CHANGE_INTERVAL
    return changeable_at if changeable_at > now else None
```

```dart
          KeptPhoto(:final id) => {'keep': id},
          NewPhoto() => {'new': next++},
        },
    ];
    final result = await _api.sendRequest((accessToken) async {
      final request = http.MultipartRequest('PUT', _api.uri('/me/photos'))
        ..headers['Authorization'] = 'Bearer $accessToken'
        ..fields['layout'] = jsonEncode(layout)
        ..fields['avatar_source'] = avatarSource.toString();
      for (final file in files) {
        request.files.add(await http.MultipartFile.fromPath('photos', file.path));
      }
      return request;
    });
    return result.when(onSuccess: (_) => const Success(null), onFailure: FailureResult.new);
  }
```
