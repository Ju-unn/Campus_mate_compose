> 앱 1.0.1 을 먼저 내고 구조 · 문구 정리는 1.0.2 에서 한다는 결정(2026-11-02) 뒤, 1.0.2 작업이 시작된 2026-11-03 저녁부터 11-04 아침까지 내린 작은 결정들을 한 표로 모은 기록이다. 한 결정에 한 파일 원칙(`docs/decisions/`)의 예외로, 이틀에 몰려 있고 서로 얽혀 있어 묶었다(`2026-10-20-launch-day-decisions.md` 와 같은 이유). 큰 결정이 되면 따로 파일을 만든다.

## 1. 흡연 칸(8 · 9번)의 세부

- 규칙 한 줄: **받는 사람이 흡연자를 싫어하고 후보가 흡연자일 때만 총점 × 0.5.** 싫어함 = 칸이 거짓, 또는 칸이 null 이고 내가 비흡연자. 칸이 참이면 감점 없음. 후보 쪽 칸은 보지 않는다. 점수와 유료 카드 이유 문구가 같은 함수(`smoking_clash`)를 쓴다(설계 §6.6a).
- 흡연자가 "싫어요" 를 골라도 된다(흡연하는 사람이 흡연하는 사람을 피하고 싶을 수 있다) — 그래서 칸은 모두에게 보인다.
- 저장은 보낸 키만 쓴다: 안 골랐으면 키를 싣지 않아 서버 값이 그대로이고, 옛 앱이 이상형 조건을 다시 저장해도 새 앱이 고른 값이 지워지지 않는다.
- **알려진 한계(앱 PR #654)**: 06-1 에서 뒤로 가 설문의 흡연 답을 바꾸고 돌아오면 06-1 칸은 처음 값 그대로 남는다(화면에 보이고 고칠 수 있다). 대장 검토의 권고("설문 답이 바뀌면 손 안 댄 칸을 맞춘다")는 복잡해서 이번에는 하지 않기로 했다.
- e2e 하네스의 점수 기준 모델은 옛 규칙 그대로다(e2e 계정은 칸이 null 이라 같은 결과) — `frontend/run.md`.

## 3. 심사원 로그인(15번)의 세부

- **입구 자리**: 시작 화면 장면(360×780)의 로고 사각형 x10 · y44 · 340×180(pen `EbdUI` 의 `MiK02`)을 화면에 cover 로 깔았을 때 닿는 자리(확대 비율 `max(W/360, H/780)`)에 투명한 탭 영역을 얹는다. 화면에는 아무것도 그리지 않고, 끄는 손길은 밑의 스크롤이 받으며, 낭독기에서도 뺀다. 소셜 로그인 버튼 영역과 같은 조건(로그아웃이 확인된 뒤)에서만 있다.
- **횟수와 시간**: `TapStreak` 가 5초 안의 탭만 세어 7번째에 열고 세기를 비운다. 7번은 사용자 결정, 5초는 코더 판단이다 — 안내문을 읽으며 또박또박(초당 1.5번쯤) 누르면 4.7초라 5초로 잡았고, 일반 사용자가 이 자리를 5초에 7번 누를 일은 없다고 봤다.
- **안드로이드 전용**: `!kIsWeb && defaultTargetPlatform == android` 일 때만 입구를 그린다(웹이 사파리에서 iOS 로 나오는 것까지 `kIsWeb` 으로 먼저 거른다). 디버그 · 빌드 값 조건은 두지 않는다 — 심사원이 스토어에서 받은 릴리스 빌드에서도 열려야 한다. iOS 빌드에는 숨은 입구가 없어야 한다(애플 2.3.1) — 코드는 모든 빌드에 실려 있고 iOS 에서는 실행 시 `_isAndroid()`(`start_view.dart:167`)로 걸러져 입구가 보이지 않는다(TestFlight 28 도 같다).
- **로그인 처리**: 시트의 이메일 · 비밀번호는 입력칸에만 있고 상태 · 로그 · 분석에 남기지 않는다. 성공해도 이동 코드는 없다 — 세션이 생기면 게이트 → 라우터가 보낸다. 사용 통계 `login` 이벤트를 남기지 않아 심사원 로그인이 로그인 수단 비율에 섞이지 않는다(`frontend/docs/ANALYTICS_EVENTS.md`).
- **운영 쪽**: 서버 · DB 코드 변경 없음. 기존 심사용 계정(id 앞 8자 `acdbb0fc`)에 관리자 API 로 비밀번호를 붙이고 로그인 이메일을 심사 안내문에 맞춰 바꿨다 — 운영 Auth 쓰기이며 사용자 승인을 받았다(`backend/DEPLOY.md` §4-16). 구글 로그인 연결(identity)은 그대로라 구글 로그인도 같은 계정으로 계속된다. 비밀번호 · 이메일 값은 저장소 밖 파일에만 있다.
- **통과 뒤 할 일**: 구글 심사 통과를 확인하면 비밀번호를 무작위로 바꿔 입구를 막는다(운영 쓰기라 사용자 승인이 먼저). 심사원이 이 계정을 탈퇴하면 되돌릴 수 없으므로 심사 안내문에 "탈퇴 금지" 를 적었다.
- **알려진 한계**: pen 시안이 없다(코드가 먼저). 오류 문구는 일반 오류 문구 그대로라 한국어다(시트 문구는 영어, 대장이 그대로 두기로 했다). 입구와 소셜 버튼이 겹치지 않는지 지키는 시험은 **PR #663(`376216d6`)으로 들어갔다**(`start_view_test.dart` 18줄 추가; 종전: 검토 권고로 남았고 아직 없었다).
